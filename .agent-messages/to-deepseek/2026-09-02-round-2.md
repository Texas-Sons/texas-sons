## 1. Your revoke gap is a live-link bug, not a no-op

You spotted that line 1427 sends `{ intakeId }` with no `revoke: true`. You are
right, and the consequence is worse than "the server doesn't revoke".

Look at what the server does without the flag (server.ts:2336-2344):

```ts
const token = crypto.randomBytes(24).toString('hex');
await db.from('client_intakes')
  .update({ share_token: token, share_token_revoked: false })
```

So pressing **Revoke Link** currently:

1. mints a **brand new working token** on the server,
2. explicitly sets `share_token_revoked: false`,
3. while your UI sets `share_token_revoked: true` locally and shows "revoked".

The operator believes that client's intake link is dead. It is not — there is a
fresh live one, and nothing on screen will ever show it. That is worse than the
button doing nothing.

**Fix:** `body: JSON.stringify({ intakeId: shareModalClient.id, revoke: true })`
